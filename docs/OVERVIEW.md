# bot-relay 概览（给人看的说明）

> bot-relay 是一台自托管的 **Bot（Agent）注册中心**：Bot 在这里登记、互相发现、
> 通过「询问—授权」交换联系方式，之后**直接互调**。它不转发消息、不存消息。
> 部署与接入细节见 `AGENT_GUIDE.md`（给 Bot 读）与 `redesign/`（PRD 与技术设计）。

## 它做什么 / 不做什么

- **做**：注册（凭邀请码）、目录（有谁、能做什么）、授权询问（A 问 B 要联系方式，
  B 亲自同意/拒绝）、联系方式受控下发、短时身份证明（互调时证明「我是注册过的某个 Bot」）。
- **不做**：不接收/转发/存储任何消息正文；不做自动同意（B 默认「放开」只指**可被询问**，
  不等于自动交出联系方式）；不做可达性探活；不兼容旧 0.1.0 中继实例（升级 = 全员重新注册）。

## 架构与信任边界（30 秒版）

```
公网（HTTPS） ──> Cloudflare 边缘 ──Tunnel──> 本机 cloudflared ──> 127.0.0.1:8080 bot-relay（唯一监听）
                                                    │                     │
                                              不开任何公网端口          SQLite（注册资料/询问/授权/审计，无消息表）

Bot A ──（控制面：目录/询问/身份证明，持访问令牌）──> bot-relay
Bot A <──（联系方式：仅当 B 亲自同意后受控下发）──  bot-relay
Bot A ──（业务调用：直连 B 的 webhook，不经 bot-relay）──> Bot B
```

- **唯一的公网入口**是 Cloudflare Tunnel；进程只监听 `127.0.0.1:8080`，宿主机不开端口。
  `TRUSTED_PROXIES` 只信任本机回环（cloudflared），来源 IP 取 `CF-Connecting-IP`，
  未受信对端伪造的代理头一律无效。
- **三种凭证**：部署者 `ADMIN_TOKEN`（管理台与程序化管理）、Bot 访问令牌（`br_`，只存哈希）、
  邀请码（`inv_`，只存哈希）。Bot 自己的 webhook 鉴权头属于登记资料，不算新凭证。
- **联系方式保密**：webhook 地址与密钥 AES-256-GCM 加密存储、日志脱敏；目录与管理台常规列表
  永远不出现；唯一下发出口是「B 同意后的受控刷新」，被撤销后刷新得到明确的 410。

## 部署者需要知道的安全要点

1. **令牌保管**：`ADMIN_TOKEN`、`ENCRYPTION_KEY`（`openssl rand -hex 32`）放 `.env` 并妥善备份。
   `ENCRYPTION_KEY` 丢失 = 所有联系方式与签名私钥**永久无法解密**；泄露则需轮换并让 Bot 重注资料。
2. **webhook 保密**是系统核心承诺：管理台查看完整凭据是「会话 + CSRF + 审计留痕」的明确动作，
   常规界面只有脱敏形态。
3. **撤销与轮换**：Bot 撤销授权即停止下发（410）；若怀疑旧值已被缓存，撤销时可一并轮换 webhook
   密钥，旧值立即作废。管理台 Bot 列表可见最近令牌/密钥轮换时间。
4. **停用**是整体开关：停用某 Bot = 目录标灰 + 不可收发询问 + 不再签发身份证明 +
   存量身份证明 ≤5 分钟自然失效。
5. **审计**：管理动作 100% 留痕（登录、邀请、停删、凭据查看、密钥轮换、询问/授权全程），
   管理台可分页查看最近记录。
6. **备份** = 数据目录（SQLite WAL 三件套）+ `.env`；恢复即换回数据目录与同一 `.env` 启动。

## 运行与观测

- 启动：`docker compose up -d --build`（宿主仅回环发布 `127.0.0.1:8080:8080`），
  或裸机 `node --env-file=.env dist/index.js`；配置项见 `.env.example`（`PUBLIC_BASE_URL`
  固定为本实例域名）。
- 健康检查 `GET /health`；指标 `GET /metrics`（需 `ADMIN_TOKEN`，Prometheus 文本，
  仅控制面指标：规模、询问结局、身份签发/核实、目录/刷新、限流与登录失败、时延直方图）。
- 管理台 `https://<域名>/admin`：登录（限流 + 会话 Cookie + CSRF）、Bot 列表与停用/删除、
  邀请码、审计视图。程序化调用可带 `Authorization: Bearer <ADMIN_TOKEN>`。
